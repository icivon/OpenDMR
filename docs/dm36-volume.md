# DM36 音量与音频增益问题（专题）

> 状态：2026-11-28 完成根因分析，**代码未改**。本文是逐项解决的清单与判据。
> 相关：`docs/dm36-porting.md`（总清单 4 节）、`docs/fd6818-registers.md`（`0x47` / `0x48` 字段定义）。

## 1. 现象（2026-11-28 用户报告，旋钮在 0 档）

| # | 现象 | 期望 | 实测 |
|---|---|---|---|
| A | 模拟模式接收 | 0 档静音 | **仍有人声** |
| B | 数字模式接收（对方发射） | 0 档静音 | 无人声，但**有轻微噪声** |
| C | 按键音 | 随旋钮变化，0 档静音 | **完全不受旋钮影响**，0 档仍满幅 |
| D | 开机音 | 随开机时的旋钮位置 | **不受旋钮影响**，始终按 `beep_volume_divider` |

四条现象不是四个独立 bug，而是同一件事的四个侧面：**DM36 上不存在“音量”这一层抽象**。

## 2. 结构：四条独立增益，旋钮只碰到其中两条

| 通路 | 增益施加点 | 旋钮是否控制 | 0 档行为 |
|---|---|---|---|
| 模拟接收 | FD6818 `0x48`（Gain1 / Gain2 / DAC 三段） | 是（但只用窄区间） | -26 dB，**不是静音** |
| 数字接收语音 | 软解调后 PCM × `vol/15` | 是 | 样本全 0，但通路仍开 |
| 按键音 / 提示音 | PCM 固定幅度 `>> beep_volume_divider` | **否**（设计如此） | 不变 |
| 开机音 | 同上，且强制 `0xFF` | **否** | 不变 |

## 3. 根因

### 3.1 `0x48` 没有静音档 → 现象 A

`docs/fd6818-registers.md:22`：`0x48` 的字段是 bits 11:10 = Gain1（0 ~ -18 dB）、bits 9:4 = Gain2（-26 ~ +5.5 dB）、
bits 3:0 = DAC（约 2 dB 一档）。

`src/board/dm36/trx_dm36.c:201-206` 当前写入 `0x3000 | (v << 4) | v`：

| 档位 | 写入值 | Gain1 | Gain2 | DAC | 合计 |
|---|---|---|---|---|---|
| 0 | `0x3000` | 0 dB | -26 dB | 0 dB | **-26 dB（可闻）** |
| 15 | `0x30FF` | 0 dB | -18.5 dB | +30 dB | +11.5 dB（理论；DAC 按 2 dB/档折算） |

两个问题：

1. **0 不是 mute**，只是最小声。安静环境下人声仍清楚，与“0 档应静音”的期望冲突。
2. **量程浪费**：Gain2 有 63 档，只用了 0–15；Gain1 恒 0 dB。曲线因此既不平滑，也吃不满动态范围。

真正能掐断 AF 的只有 `0x47 = 0x6040`（`AF_MUTED`）或关功放（`PIN_AUDIO_AMP`）。

### 3.2 数字模式也写 `0x48`，覆盖 DMR 表的鉴频电平 → 现象 B 的主因

调用链**没有任何模式判断**：

```
input.c（电位器变化）
  → radio_rx.c:182-186  apply_knob_volume()   // 无条件
  → trx.c:159-165        trx_set_volume()     // 只判 drv 是否就绪
  → trx_dm36.c:201-206   set_volume()         // 无条件写 0x48
```

而数字接收进信道时，DMR 表（`trx_dm36.c:102`）写的是 `0x48 = 0xB2F5`，这个值决定送进 codec ADC 的鉴频幅度：

| 来源 | 写入值 | Gain1 | Gain2 | DAC | 合计 |
|---|---|---|---|---|---|
| DMR 表 | `0xB2F5` | -12 dB | -2.5 dB | +10 dB | 约 **-4.5 dB** |
| 旋钮 0 档 | `0x3000` | 0 dB | -26 dB | 0 dB | 约 **-26 dB** |
| 旋钮 6 档 | `0x3066` | 0 dB | -23 dB | +12 dB | 约 -11 dB |

**在数字信道上拧旋钮 = 把软解调的输入电平砍掉 6～21.5 dB**，0 档最狠。软解调电平不足 → 解不出语音 → “没人声”；
而通路仍然开着 → 剩下的底噪就是“轻微噪声”。

结论：**数字模式的音量只应作用于 PCM（`dmr_sound.c` / `voice_play.c` 已经在做），完全不应该写 `0x48`。**
`0x48` 在数字模式是“射频/基带参数”，不是音量。

### 3.3 0 档只把样本乘 0，没有关通路 → 现象 B 的次要成因

- `dmr_sound.c`、`voice_play.c:190-193`：`vol = 0` 时 PCM 全 0；
- 但 `radio_rx.c:755-760` 的 `radio_dmr_audio(true)` 照样打开功放；
- codec DAC 增益 `dmr.c:170` 仍是 `factory_cal_rx_dac_gain()`，从未 mute。

于是喇叭里剩下的是 **codec DAC 自身噪底 + 功放噪声**。0 档应当是“关掉这条通路”，而不是“喂 0 样本”。

### 3.4 提示音与开机音绕过主音量 → 现象 C / D

- **这条是 DM36 分支自己在 2026-11-28 引入的，不是上游行为。** `git diff origin/develop -- src/services/voice_play.c`
  显示上游只有 `v = (voice ? x[i] : 0) + (b ? bx[i] : 0)`，**没有任何音量缩放**；`/15` 与
  “must still be heard at level 0”的注释都是本分支当天加的（见 4 节：上游 DM32 不需要软件音量）。
- `sound.c:318`：`shift = (next_volume >= 0) ? next_volume : settings.beep_volume_divider`，与旋钮无关；
  `beep_volume_divider` 是独立的“提示音音量”菜单（0–10 档，约 6 dB/档）。
- `sound.c:412` 与 `sound.c:422`：开机音用 `sound_play_volume(..., 0xFF)`，`0xFF` 的语义就是“取 `beep_volume_divider`”，
  等于主动丢弃旋钮值。

### 3.5 开机音还有时序问题 → 现象 D 的第二成因

`main.c:134` `input_start()` → `main.c:139` `sound_play_boot()` 几乎紧挨着。
而电位器第一次读数在 input 任务里还要做“连续两次 raw 一致”判定（`input.c:168-187`，含 20 ms 延时）。
开机音播放时，`rx_vol_target` 可能**还没被赋值**；即使已赋值，`0xFF` 也会把它丢掉。

## 4. 上游事实：DM32 的音量根本不在软件里

三处证据（`git diff origin/develop`）：

| 位置 | 上游（DM32） | DM36 分支现状 |
|---|---|---|
| `radio_rx.c` 进模拟信道 | `trx_set_fm(factory_cal_analog_rx_volume())`，固定标定值 | 加 `rx_vol_set ? rx_vol_target` 与 `trx_set_volume()` |
| `voice_play.c` 混音 | 语音 + 提示音直接相加，**无缩放** | 语音 ×`vol/15`，提示音不缩放 |
| `dmr_sound.c` 解码后 | 只做 AGC 与限幅，**无缩放** | 再乘 `vol/15` |

结论：**上游 DM32 的接收音量是纯硬件电位器**，串在音频通路上，MCU 既不读它也不写任何音量寄存器。
所以“0 档全静音”是硬件给出的事实——语音和提示音被同一只电位器一起衰减到零。

DM36 把电位器改接 ADC ch0，硬件音量链路不存在了，**软件必须重建同一只“电位器”**：

1. 它在**最终音频混合之后**，对语音和提示音一视同仁 → 0 档全静音，与上游等价；
2. 模拟接收那段音频不经过软件（FD6818 AF 直连喇叭），只能用寄存器模拟同一只电位器 → 放板级
   `trx_dm36.c` 的 `set_volume()`；
3. 除此之外**不新增任何共享层门控**（上游没有 `rx_volume_audible()` 之类，加了就是给 DM32 引入回归风险）。

## 5. 设计原则（已确认）

1. **0 档 = 全静音**：语音、提示音、开机音、数字底噪都为 0。
2. **以上游为准**：共享层只保留“一处缩放”替代硬件电位器；DM36 的芯片差异全部放 `board_dm36.h` 与 `src/board/dm36/*`。
3. **DM32 逐字节不变**：任何新代码必须由板级宏或板级文件承载。

## 5.1 电位器行程实测（2026-11-28，复核）

工具 `tools/debug/dm36_volwatch.py`：直接 `call adc_read_volume()`（符号取自**已刷固件**的 ELF），
每 250 ms 一次、共 577 次读数，两端各保持 5 s 以上，按“相邻读数差 ≤ 2”切出稳定段。

| 位置 | 稳定段 | 均值 | 抖动 |
|---|---|---|---|
| 逆时针到底 | 0（337 + 112 次全 0，另有一段进入时的 0..2） | 0.0 | 0 |
| 顺时针到底 | 688..689（21 次） | 688.7 | ±1 LSB |

- 行程 = **0 .. 689**（ADC 为 10 位，`& 0x3FF`；上端只到 690 是电位器前端分压所致，不是满量程）。
- 映射（2026-11-28 按用户要求改为 **16 等分**）：`level = (raw * 16) / 690`，结果 `> 15` 钳到 15。
  每档在行程上等宽 43–44 码，**两端档位不再只有半格**：

  | 档 | 0 | 1 | 2 | … | 7 | 8 | 9 | … | 15 |
  |---|---|---|---|---|---|---|---|---|---|
  | raw 起点 | 0 | 44 | 87 | … | 302 | 345 | 389 | … | 647 |
  | 宽度 | 44 | 43 | 43 | 43 | 43 | 44 | 43 | 43 | 43（到 690） |

  旧公式 `(raw*15 + 345) / 690` 是“15 等分 + 端点半格”（0 与 15 档各只有 23 码，约中间档一半宽），已弃用。
- 电位器两端有机械限位，读数稳定无漂移；噪声 ±1 LSB 远小于 43 码档宽，不需要滤波。
  唯一注意：旋钮恰好停在边界 ±1 码时档位可能来回跳，若刷机后遇到再加 2 码迟滞。
- 与旧记录一致（0..690，632 / 251 是半途松手的读数）；复测命令：
  `python3 tools/debug/dm36_volwatch.py --secs 20 --port /dev/ttyUSB0`。

## 6. 待解决任务（逐个执行，按依赖排序）

编号 `V1…V7`，完成一项就在此勾选并记录刷机/验证结果。

### V1 把“软件电位器”放回混音之后（全静音的落点，先做）✅ 已实现 2026-11-28，待刷机验证
- 目标：语音与提示音共用同一个 `level`，0 档一起消失——等价上游那只硬件电位器。
- 改点：`voice_play.c` 的 `write_block()` 改回上游结构再整体缩放：
  `int32_t v = ((voice ? x[i] : 0) + (b ? bx[i] : 0)) * (int32_t)vol / 15;`
  同时删掉 11-28 加的“提示音在缩放之后”注释。
- 实现（2026-11-28）：新板级开关 `BOARD_VOLUME_SCALES_PROMPTS`（`board.h` 默认 0，`board_dm36.h` 置 1）。
  DM32 走 `#else` 保持 HEAD 原样；`cmp` 对比基线产物只有 7 字节差异，全部是 `__TIME__` 字符串，代码段一致。
- 判据：0 档按键音与语音同时消失；1/8/15 档按键音随档位变化；`beep_volume_divider` 仍能压低提示音。
- 风险：`beep_volume_divider = 0` 的历史爆音（MEMORY 铁律 5），改后必须再确认该值不炸。

### V2 数字语音缩放与 V1 对齐
- 目标：数字语音走同一个 `level`，不再各自为政。
- 改点：`dmr_sound.c` 的 `vol/15` 保留，系数先与 V1 一致（V7 再换成查表）。
- 判据：数字 0 档语音消失；6 档与当前响度相当。

### V3 数字模式不写 `0x48`（只是“别动射频参数”，不是静音手段）
- 目标：拧旋钮不改变数字解调电平。
- 为什么：`0x48` 在数字模式是射频/鉴频参数（DMR 表 `0xB2F5`），不是音量。旋钮写它就是砍解调电平
  （0 档比 DMR 表低 21.5 dB），这是“数字 0 档没人声”的真正原因。
- 改点：`trx_set_volume()` 或板级 `set_volume()` 判模式：数字时只缓存，进模拟时下发。
- 判据：数字信道 0↔15 来回拧，`dmr_soft_stats` 的同步/解码计数不掉、语音不断。
- 注意：**不要**把这一项当成 0 档静音的方案；0 档静音由 V1（数字）与 V4（模拟）负责。

### V4 模拟 0 档静音（板级，DM32 不经过）
- 目标：模拟信道 0 档贴耳无声，1 档能听。
- 改点：`src/board/dm36/trx_dm36.c` 的 `set_volume()`：`level == 0` → 写 `0x47 = BOARD_AF_MUTED`（0x6040）；
  `level >= 1` → 写回 `BOARD_AF_FM_WORD`（0x6943）再写 `0x48`。
- 判据：模拟 0 档无声、1 档正常；切到数字信道后 `0x47` 没被留在静音值。
- 风险：每次调谐都会重写 `0x47`（`set_demod()` / `tune_channel()`），要保证调谐完仍按当前档位。

### V5 数字 0 档底噪（先测来源再改）
- 目标：0 档除了语音消失，底噪也消失。
- 先测：0 档有载波时把 `PIN_AUDIO_AMP` 临时拉低——噪声消失 = 功放/DAC 底噪；不消失 = 鉴频串音。
- 改点（按测量结果二选一）：功放侧用板级宏叠加“音量 0 不 open”，或 codec DAC 置静音值。
- 约束：不要因此在共享层加 `rx_volume_audible()` 式门控（上游没有，见第 4 节）。

### V6 开机音：跟随旋钮 + 时序
- 目标：开机音按开机瞬间的旋钮位置播放，0 档不响。
- 改点：`sound_play_boot()` 去掉 `0xFF`（`sound.c:412/422`）；`main.c:139` 移到首次电位器读数之后，
  或播放前同步读一次 ch0。
- 判据：最小/中间/最大三种位置开机响度对应；最小端完全无声；延迟 < 200 ms。

### V7 模拟 ↔ 数字等响校准
- 目标：同一档位切模式不跳音量。
- 改点：V1/V2 的线性 `/15` 换成与 V4 的 `0x48` 实测 dB 对齐的查表。
- 判据：同源同档，两种模式响度差 < 3 dB。

## 7. 验证顺序（改之前先测，避免再猜参数）

1. **验证 3.1**：模拟信道，档位 0 → 确认人声仍在（预期在）；再记 1 / 6 / 15 的响度差。
2. **验证 3.2**：数字信道，档位 0 → 6 → 15，听语音是否随档位恢复；同时看 `dm36_rfwatch.py` 的
   `dmr_soft_stats` 同步/解码计数在 0 档是否掉下去。**这一步能直接判定 3.2 是否为主因。**
3. **验证 3.3**：数字信道 0 档、有载波时临时把 `PIN_AUDIO_AMP` 拉低（或 `0x47 = 0x6040`），看噪声是否消失，
   区分“DAC/功放噪底”与“鉴频串音”。
4. **验证 3.5**：旋钮最小端开机，用示波器/耳朵确认开机音是否在第一声就已是 0 档响度（当前不是）。

## 8. 决策点

1. **0 档语义：已定 —— 全静音**（语音、提示音、开机音、数字底噪全为 0）。依据：上游 DM32 是硬件电位器，
   0 档物理上全静音；DM36 的软件音量应等价复现，不引入第二套语义。
2. **`beep_volume_divider` 去留**：保留为提示音上限（V1 让 `level` 与它相乘），暂不删除。
3. **`0x48` 曲线**：先只做 0 档静音，1–15 阶梯维持现状；是否用满 Gain2 全量程重做 16 档表，
   等 V4 实测 1/6/15 之后定（需 15 次测量）。

## 10. V9 提示音：固定音量并降低（2026-11-28 晚，取代 V8）

用户原话：**"音量旋钮既然无法解决，先按固定音量，降低开机音量和按键音。"**
背景：先按 V8 试过让提示音跟随旋钮（`percent` 乘在 `note()` 里），
`docs/dm36-porting.md` 4.1.1 也证实这块板的 FM 子板是 FD6818B（BK4829）而不是问题所在；
旋钮到基带 DAC 的提示音通路在硬件上够不到，所以 V8 作废，改回"固定值"，并且**把固定值降低**。

### 10.1 提示音的音量从哪里来（不变的部分）

- `sound.c` 的 `note()` 只有一个衰减：`sine[*index] >> shift`，`shift` 来自
  `next_volume`，它为 -1 时就是 `settings.beep_volume_divider`（菜单"提示音音量"，0..10，
  菜单按 `(2 - divider) x 3 dB` 显示，出厂 4 = -6 dB）。
- 开机音 `sound_play_boot()` 与按键音 `sound_play()` 都传 `0xFF` = "用菜单值"，所以两者同源。
- 基带 DAC 的增益固定（`GCR_DACL`），**旋钮（电位器）完全不参与**，V8 想越过硬件去接旋钮，
  已否决。

### 10.2 本次改动

1. **回退 V8**：删掉 `note()` 的 `percent` 参数、`sound_task()` 的百分比计算、`radio_prompt_percent()`
   的声明与实现。提示音重新只由 `shift` 决定。
2. **降低固定值**，只针对**按键音与开机音**（用户点名的两处）：
   - `board.h` 新增默认 0 的 `BOARD_PROMPT_DIVIDER_MIN`；
   - `board_dm36.h` 定义 **6**（即 -12 dB，比出厂 4 再降 6 dB，幅度 1/64）；
   - `sound.c` 的 `prompt_divider()` 取 `max(settings.beep_volume_divider, BOARD_PROMPT_DIVIDER_MIN)`，
     `sound_play()` 的按键音与 `sound_play_boot()` 的两条路径用它；其它提示音（低电量、错误音、
     发射提示音）仍按菜单值不动。
3. 菜单仍可**更轻**（7..10），不能更响（0..5 被抬到 6）。菜单显示的 dB 只对其它提示音准确，
   按键音/开机音比它低 6 dB —— 这是"先固定"的临时状态，用户确认后再决定是否改成独立设置项。
4. DM32 侧：`BOARD_PROMPT_DIVIDER_MIN` 为 0，`prompt_divider()` 整体被 `#if` 排除、
   `BOOT_PROMPT_VOLUME` 仍是 `0xFF`，DM-32 产物不变。

### 10.3 判定

- 开机音、按任意键：比改动前（-6 dB）**明显轻**，但仍听得到；不再有"叮"一下很响的感觉。
- 信道语音、DTMF、1750 Hz 单音：**不变**（DTMF 与 1750 仍走菜单值/满幅，不参与本条）。
- 模拟/数字收发音量与改动前一致。

### 10.4 风险与退路

- 1/64 幅度（-12 dB）在嘈杂环境可能偏轻。要再调只改 `board_dm36.h` 的
  `BOARD_PROMPT_DIVIDER_MIN`（7 = -15 dB，5 = -9 dB），不要动 `note()` 的算法。
- 若日后确认旋钮在硬件上能到提示音通路（换板/改线），再把 V8 的设计捡回来；届时仍要保留
  "DTMF/1750 不缩放"这一条。
