# DMR 软件同步试验（2026-11-20）

想法：DMR 也像 NXDN / M17 一样从 8 kHz 鉴频器录音软件解调。结论：弱信号下明显不如 HR_C7000 自己的 DMR 接收，不采用。

- `py/dmr_lab.py`：同步字最小二乘拟合（每符号 5/3 个采样点，三次插值），对热点测试文件逐符号比较。
- `py/dmr_frames.py`：从突发取出 AMBE+2 帧，按我们解码器的规则（C0 + C1 纠错数 > 3 为坏帧）统计；`--bit` 统计
  `tools/debug/rx_capture.py` 抓到的芯片帧；`--v2` 是全局时间轴 + 判决引导的版本。

结果（约 −115 dBm，两台拔天线、发射机不插编程线）：

| | 芯片 | 软件 |
|---|---|---|
| 坏帧 | 1.2% | 约 21% |
| 漏同步 | 无 | 约 1/5 的超帧 |

强信号下两者都是 0 错。试过全局时间轴、判决引导的定时 / 增益 / 直流、突发内直流漂移、匹配滤波：都只有边际改善，瓶颈
在 8 kHz 录音（每符号 1.67 个采样点，FM 模块的固定速率）。

顺带发现：我们固件 DMR 发射在同样弱的信号下每个突发的第 1 个 AMBE 帧坏 46%（第 2、3 帧 4%、1%），另一台机器没有这个
问题，待查。

## 更正（同日，已知内容 + 正确统计）

上面"软件差 10–20 倍"的结论是统计方法造成的：录音里有发射开头的语音头 / 数据突发、两次发射之间时间轴跳变，按一个
同步往前后外推就会把整突发的垃圾算成坏帧；另外 soft_ / weak_ / dmrtone_ 都是我们自己的发射机（第 1 帧坏）。

- `py/dmr_tone.py`：发射机 `vocoder_tx_test=1`（每帧都是 1031 Hz 音调帧），芯片 `.bit` 或录音都按"纠错后全对"打分。
- `py/dmr_tune.py`：滤波 / 电平方式对比。
- `py/dmr_eval.py`：按时间轴段（一段 = 一次发射，至少 2 个同步）只取语音超帧，按突发内位置统计坏帧。

接收链：RRC 0.2 → 每突发判决引导四个电平（阈值取簇均值中点）→ 固定 3 抽头均衡 [-0.05, 0.95, -0.05]（8 kHz 每符号
1.67 点，RRC 后有符号间干扰；交叉验证训练出的系数两次都是这个）→ 切片。

| 第 2、3 帧（约 −116 dBm） | 坏帧 | 0 错帧 | 纠错后全对（音调） |
|---|---|---|---|
| 芯片 chip_tone.bit | 0.3 % | 33 % | 67 % |
| 软件 原始 | 9.8 % | 22 % | 29 % |
| 软件 RRC + 判决电平 + 均衡 | 0 % | 77 % | 约 90 % |

另一台发射机 other_*：原始和新接收链都是 0 坏帧（0 错帧 70 % → 83 %）。注意芯片和录音不是同一时刻录的。

## 固件实现（同日）

DMR 信道的接收改由软件完成（`src/services/dmr_soft.c`），发射仍由 HR_C7000 引擎完成：按 PTT 时停录音、交给引擎发，
发完恢复录音。`dmr_soft_enabled = 0`（串口）切回芯片接收做对比；热点模式仍用芯片。

- `dmr_demod.c`：RRC → fsk4 采样环；捕获时每 1/3 采样点用"采样符号位 + 64 位掩码"先筛 4 种语音同步字（数据同步是其反相），
  再最小二乘拟合；锁定后每 30 ms 一个突发，同步在预期位置 ±1 采样内找，突发内判决电平 + 3 抽头均衡；偏离时间轴的强同步
  （另一次发射）直接换时间轴。设备上不能用 64 位除法（第一版每半块 113 ms）。
- `dmr_l2.c`：按 TS 102 361-1 自己实现：同步字分类、Slot Type Golay(20,8)、EMB QR(16,7,6)、TACT Hamming(7,4)、
  BPTC(196,96)、RS(12,9)+掩码（纠 1 字节）、嵌入式 LC（B.2.1）。
- `dmr_soft.c`：时隙（基站：CACH 的 TC 指后一个突发；直通 TDMA：同步字；MS：信道时隙），语音头/嵌入式 LC 开始通话，
  终止帧或超时结束；EMB 必须和本次通话色码一致（QR 随机通过率约 1/4）；没有同步的 A 突发只在 mse < 0.30 时接受。
- 公共部分：`fsk4.c`、`afrx.c`、`afrec_*`，NXDN / M17 也用。
- PC 测试：`c/l2_test.c`（热点测试帧文件）、`c/demod_test.c`（录音，按超帧打分）、`c/burst_look.c`（突发日志）。

实测：

| | 芯片 | 软件 |
|---|---|---|
| 对讲机直通 −116 dBm，第 2、3 帧坏帧 | 0.3 %（之前） | 0 %（纠错后全对 92 %） |
| 热点双时隙 −122 dBm，坏帧 | 14.3 % | 约 2.6 % |

发现：我们芯片引擎的直通发射不发终止帧（最后约 25 ms 是无调制载波）。
